# 2 分钟演示视频脚本

> 录制方式：OBS 或 Win+G 录屏，只录浏览器窗口 + 你的声音。不要露脸。
> 语速控制在每分钟 300 字左右，总台词约 560 字。
> 提前把服务跑起来，浏览器开好 http://127.0.0.1:8000 （或公网链接）。

| 时间 | 画面 | 台词 |
|---|---|---|
| 0:00–0:15 | 首页，鼠标停在输入框 | 我是北邮通信工程大一的学生。今年九月，我因为漏看一条群通知，错过了一届全国大学生数学竞赛。通知不是不存在，是它只存在三天。 |
| 0:15–0:35 | 点「竞赛通知」→「开始解析」 | 所以做了「通知雷达」。它不只帮你记通知，它帮你做决定。粘一条通知，五个 Agent 接力跑完。 |
| 0:35–1:00 | 结果页：倒计时 + 匹配度环 | 几毫秒出结果。高分，强烈建议。但真正重要的不是分数，是下面这些—— |
| 1:00–1:20 | 滚动到「引用条款」区 | 每一个判断都有出处。它引用了知识库里推免加分规定的原文，还告诉你"这条赛事是否进目录尚未核实"。**它敢说"不确定"**，这比给个漂亮分数重要。 |
| 1:20–1:35 | 指着两个截止节点 | 这条通知有两个截止日：报名那个已经过了，标灰；提交那个还剩几天。市面上的工具只会告诉你一个，你会看错。 |
| 1:35–1:55 | 点「矛盾通知（测自审）」→ 解析 | 现在粘一条日期写错的通知：活动是 11 月 10 号，报名截止却写 11 月 25 号。第五个 Agent 是 Critic，专门审查前面四个。它抓到了矛盾，**打回重跑**；第二轮结论自动降为"待核实 / 30 分"。屏幕上没有任何一处自相矛盾。 |
| 1:55–2:10 | 切到码道对话记录 | 五个 Agent：抽取、校验、检索、评估、自审。全部用华为云码道写成，十二轮对话，从建工程到修 bug。中间我否决了它五次——第一版它给我做了个通知聚合器，那是另一个产品。 |
| 2:10–2:20 | 微信反馈截图（打码）→ 验收表 | 三个同学各拿自己群里的通知试了，都说倒计时和分数一眼看懂。我另外压了 30 条真实通知：第一版截止日期只对 20%，现在 30 条全对。 |

## 录制注意

1. **先说结论**：前 15 秒必须出现"我错过了一届数学竞赛"，这是唯一别人抄不走的东西。
2. Critic 那段是全场记忆点，语速放慢，让红色警示条和"自审拦截 1 次·已修正"徽标在画面上停 2 秒。
3. 不要念功能清单，不要念技术栈。
4. 结尾不要"谢谢观看"：如果还没攒到 3 个真实用户，就把最后一句改成"现在我在找第一批用它的人"，不要编。
5. 录完检查：有没有出现你的微信/学号等隐私信息（截图里的群名要打码）。
6. 录之前先把「矛盾通知（测自审）」这个 chip 里的日期确认一遍，必须满足"活动日期早于截止日期"，否则 Critic 不触发，整段演示就废了。
7. **台词里不写死分数和日期**。先用要出镜的那条通知跑一遍，把屏幕上的分数、节点数、剩余天数念准再录。
   注意：本地版和码道版的打分数值不一样（同一条竞赛通知，本地 93、码道 65），两版不要混着一套台词讲。
8. 出镜用哪一版就固定用哪一版：本地版功能全，码道版留痕真。**建议本地版出镜，码道版只出截图。**

## 素材在哪（录前对照）

| 画面 | 文件 | 怎么出镜 |
|---|---|---|
| 首页 + 决策卡 | 浏览器 `http://127.0.0.1:8000` | 实时操作，边点边讲 |
| 矛盾通知（自审拦截） | 页面上「矛盾通知（测自审）」chip | 实时点，让红色警示条停 2 秒 |
| **压测验收表** | `docs\验收表.html` | 浏览器打开，截屏或直接拍 |
| 码道对话过程 | `codearts-trace\` 共 11 张（见 `索引.md`） | 选 `03-真bug修前输出`、`04-真500与KeyError`、`09-自审拦截两轮` 三张 |
| 用户反馈 | **还没有** | 录之前找 3 个同学试用，要一句原话；要不到就别放这一屏，别编 |

> 用户反馈是最容易造假也最容易被问穿的一栏。没有就不放，评委不会因为"没找用户"扣分，
> 但会因为"编了用户"扣分。
