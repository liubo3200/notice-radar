### 2. 改契约：单条决策（已发）

```
先停一下，方向要改。

我看了你写的接口，是批量列表 + summary 统计，这不是我要的产品。
我的定位是"帮一个学生决定：这一条通知，我要不要花时间"。一次只判断一条，
用户已经知道通知在哪了，不需要我们再帮他管列表。

请把 /api/parse 的返回改成"单条决策"结构，字段名照抄，不要自己加：
{
  "fields": {"event_name","deadline","event_time","target","organizer","category","link","deadlines":[{"label","date"}]},
  "check": {"confidence":"高|中|低","warnings":[],"days_left":null},
  "retrieval": {"hits":[{"source","excerpt","score"}],"grounded":true},
  "evaluation": {"worth","score","reasons":[],"risks":[],"actions":[],"basis":[{"source","excerpt"}]},
  "critic": {"verdict":"pass|reject","issues":[{"level","code","message","fix"}],"round":1},
  "fallback": false
}
worth 只允许这六个值：强烈建议 / 可以考虑 / 不建议 / 已截止 / 信息不足 / 待核实。
只要单条。把之前那套批量循环和 summary 全删掉，不要保留兼容分支。
```

### 9. 自审 Agent Critic（升级 2）

```
新增 core/critic.py：审查 evaluator 的输出，抓三类矛盾——
① deadline 早于今天却判断"可报名"；② event_time 与 deadline 冲突（活动时间早于截止）；
③ event_name 为空却给出"强烈建议"。
发现问题返回 issues 列表（code/message/fix），verdict=reject 时由主流程打回重跑一次，
最多重跑一次，二次仍 reject 就在 warnings 里写明"已重试仍未通过"，不要无限循环。
另外多截止日、截止日期靠推断得出，这两类给 warning 不阻断。

关键：判 E2 时间冲突时，打补丁要把结论也一起降级成"待核实"，
不能出现"自审已拦截"和"强烈建议 90 分"同时显示在屏幕上。
```
截图要点：**现场演示的核心**——粘一条活动时间早于截止时间的通知，让 Critic 抓出来。

### 11. 修 bug：多截止节点

```
我发现一个问题：一条通知里有"报名截止"和"作品提交截止"两个日期时，
之前只取最早的那个，用户会以为只剩一个截止日。
改成把所有截止节点都抽出来（label + date），主倒计时取最早未过期的，其余全部展示。

另外补两个我踩到的坑：
① "比赛时间/参赛时间"是赛程，不是报名截止，有报名节点时不要把赛程节点混进截止列表；
② 日期写在下一行的情况（标签一行、日期一行）也要能取到，但只对短标签行
   （≤20 字且含报名/提交/办理/申报/报送/时间/截止）跨行取，否则会抓到文末落款日期。
```
截图要点：改前 / 改后各一张。**评委最想看到的就是这种"发现问题 → 定位 → 修复"的闭环。**

### 12. 30 条真实通知压测 + 十类误判闭环

```
现在做真实数据压测。我把 30 条北邮校内通知放进了 testset/clean/（01.txt ~ 30.txt），
人工标注在 testset/labels.md，写了每条的正确答案（截止日 + 该不该参加）。
写一个 tools/accuracy.py，跑全部 30 条，输出两个准确率：截止日期正确数、结论方向正确数，
并列出每一条错在哪。

首轮结果很差（截止日 20%、方向 90%）。我逐条看完，误判集中在这十类，请你按顺序修：
1. 发布时间被当成报名截止日 → 剔除"发布时间/发布日期/浏览次数"这类元信息行；
2. 讲座的举办日被当成报名截止 → 分离 deadline 和 event_date；
3. 面向青年教师的比赛学生不能参加，却打 83 分 → 资格判断前置；
4. "各学院报送案例"这类给老师看的通知被打高分 → 检测行首"各学院/各教学单位"+ 正文无"同学"；
5. 停水通知被当机会 → 新增"事务"类别并直接排除；
6. "报名时间"被当成活动时间，误触时间冲突 → 取活动时间时排除报名/截止/提交/申请行；
7. "于11月13日下班前"这种没有"截止"字样的写法漏抽 → 加"于…前"模式兜底；
8. 售房、充值、通行证没被识别为事务 → 扩充事务词表；
9. 表格型通知（截止时间在表格里）抽不到 → 处理表格行；
10. 标题含"招新/招募/征集"却被判成竞赛 → 类别判断标题优先于正文。

每修一类，重跑 accuracy.py，把前后数字发我。最后要跑到截止日 30/30、方向 30/30。
```
截图要点：**这是全片最值钱的一屏**——首轮 20% 到 30/30 的曲线 + 十类误判的修复记录。
建议把每轮的 `accuracy.py` 输出留在对话里，别删。
