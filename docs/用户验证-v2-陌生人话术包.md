# 真实用户验证 v2 · 陌生人试用话术包

> 目的：把「3 个熟人 + 只夸好看」升级为「5 个陌生人 + 能指出问题」。  
> 对应评分：加分项「有真实用户使用与反馈验证 +3」；决赛「创新性与落地价值 25 分」里的佐证。  
> 关键：**不要引导、不要解释、不要站旁边指屏幕**。你要的是他卡住的样子，不是他的好评。

---

## 一、找谁（4 天内凑 5 人）

**避开**：同班同学、室友、一起打比赛的、已经听你讲过这个项目的。

**优先**：

| 优先级 | 人选           | 理由                      |
| --- | ------------ | ----------------------- |
| 1   | 大二/大三学长学姐    | 他们真的在关心保研、竞赛、志愿时长，是目标用户 |
| 2   | 其他学院的本科生     | 画像不同，能暴露"规则加权不是万能"的问题   |
| 3   | 社团/学生会里管通知的人 | 知道通知有多乱，能给出真实痛点判断       |



---

## 二、开场（复制即用，别改）

> 打扰一下，我在做一个校园通知的小工具，想请人帮我试 3 分钟，不用注册、不用装东西，打开链接就行。  
> 你就当平时收到一条通知，看看它给的东西对你有没有用。**做得不好的地方你直说，我正好要改。**

要点：

- 说「3 分钟」，不要说得像访谈（否则对方会客气）
- 明说「直说不好」，降低他夸你的压力
- 不透露你是作者里"做得好"的部分，只说"要改"

---

## 三、四步流程（全程你不解释）

**第 1 步｜给链接，让他自己打开**  
`https://liubonoticeradar.pythonanywhere.com`  
只说一句："你随便点一个示例，或者粘一条你群里最近的通知。"

**第 2 步｜看他第一眼落在哪**  
不要说话。记住他第一眼看的是：倒计时？分数？还是标题？看他有没有犹豫、来回滚动。

**第 3 步｜问三个问题（按顺序，别跳）**

1. 「**这条通知，你现在会去做吗？**」  
   —— 测他的决策是否被改变。如果他说"我本来就会去"，追问："那这个工具多给了你什么信息？"
2. 「**你最不信它哪一句？**」  
   —— 这是最关键的一问。大多数人会说"分数凭什么这么高"或"这个依据跟我有关吗"。  
   如果他答"都挺信的"，追问："那如果它算错了，你怎么发现？"
3. 「**如果它告诉你别去，你会听吗？**」  
   —— 测结论的说服力，也测他的风险感知。

**第 4 步｜收尾**  
"够了，谢谢。" —— 不要问他"好不好用"，那一问只会得到"挺好的"。

## 五、怎么判读（不要自我安慰）

| 现象                 | 结论         | 该怎么改                       |
| ------------------ | ---------- | -------------------------- |
| ≥2 人说「最不信分数」       | 打分的可解释性不足  | 决策卡里把加减分明细展开，别只给总分         |
| ≥2 人说「依据跟我无关」      | 知识库覆盖不够    | 明确标"这条依据来自哪份文件、适用谁"        |
| ≥2 人说「不会去做 / 本来就会」 | 结论没有增量价值   | 说明"它比你自己看多给了什么"，或补"机会成本对比" |
| 有人说「不知道点哪里」        | 交互有硬伤      | 立刻改，这是必改项                  |
| 全员说"挺好的"           | **这次验证失败** | 换人重来，不要写进材料                |

## 六、五件不要做的事

1. **不要替他操作**。他卡住才是信息。
2. **不要解释功能**。一解释，你测的就是你的讲解能力。
3. **不要问"好不好用"**。只会得到"挺好的"。
4. **不要把"挺好的"写成反馈**。写进材料后，答辩一问就穿。
5. **不要只找熟人**。熟人的反馈天然偏向你，评委也知道这一点。

## 七、写进材料的格式（凑够了就贴这段）

```markdown
### 真实用户验证（5 人，2026-11-18/19）

| # | 身份 | 反馈原话 | 暴露的问题 |
|---|---|---|---|
| S1 | 大二 信通 | 「……」 | …… |
| S2 | 大三 计算机 | 「……」 | …… |

**共同问题**：X 人说「……」，已改为「……」。
**仍未解决**：……（如实写）
```

有「暴露的问题 + 已改」这一栏，这一项才是真验证；只有好评，等于没验证。

## 八、外校的人能不能测？（能，但只测三件事）

**结论：能，但配额是 3 校内 + 2 校外，不能全用外校。**

理由很直接：这个作品的核心价值是「按北邮画像判断值不值得」——知识库里只有《推免竞赛加分等级》《本校人机协作大赛情报卡》《志愿服务认定》。外校人问"这对我值不值得"，答案对你没有意义；但他能测的三件事，本校人反而测不出来（太熟了）。

| 让外校人测 | 为什么非他不可 |
|---|---|
| ① 字段抽取准不准（截止日、多个节点分开算） | 他粘的是**你没见过的别的学校的通知**，格式差异才是真考验 |
| ② 倒计时与日历下载能不能用 | 通用能力，跨校一样 |
| ③ 交互卡不卡、自审拦截能不能看懂 | 没有你的先验知识，卡住的地方就是真卡点 |

**不要问外校人**：「这条通知你会去做吗」「这个分数合不合理」——他的答案对北邮画像无效。

### 他粘自己学校通知时，会发生什么（已实测）

拿一条外校数学竞赛通知跑现在的线上版本：

```
类别 竞赛 | 截止 2026-11-25 | 剩余 8 天
结论 强烈建议 80 | grounded=false | 引用 0 条
自审 W3_LOW_CONF_STRONG + W4_NO_BASIS_STRONG
```

即：**不会错引北邮的规定**（引用 0 条，没有硬凑），但会明确提示「知识库里没有匹配到可引条款，这个强烈建议只来自规则判断，没有出处」。

所以第 4 步收尾时加一问（只对外校人问）：

> 「屏幕上哪里能看出，这个结论**没有**校规依据？」

- 他一眼找得到 → 提示做得够清楚，写进材料。
- 他找不到 → 说明提示不够显眼，这是必改项。

### 写材料时别混着写

5 人里注明清楚，例如「3 位北邮在校生 + 2 位外校本科生」。评委看到混合样本会认为你懂用户边界；写成"5 位同学"反而像凑数，一问就穿。
